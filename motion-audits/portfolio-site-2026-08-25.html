Overall

This site's motion is already better than most AI-generated portfolios: custom Bézier curves everywhere instead of default ease, scroll reveals via IntersectionObserver rather than scroll listeners, and a genuine prefers-reduced-motion block that covers CSS and the 3D scene. The problems are at the edges: the contact form's state changes snap instantly (the one place users actively wait for feedback), the marquee runs unconditionally, and the reveal system applies one identical animation to every section regardless of hierarchy. Fix the form, gate the marquee, and this is production-grade.

CriticalEmilJakub

Form status text snaps between states with no transition

WhatThe contact form's status line ("Sending..." → "Sent. I will get back to you soon.") swaps instantly via textContent. This is the single highest-stakes feedback moment on the page — a visitor just handed over their details and is watching for confirmation.

Why it mattersInstant state swaps at the moment of submission read as "did it work?" Emil's frequency rule: this is a rare, high-anxiety action — exactly where a small transition earns its keep. A crossfade also masks the text-length jump between states.

Recommended motionCrossfade + 4px rise on state change: old text fades down-out 120ms, new text fades up-in 180ms with 2px blur clearing. One CSS class toggle, no library.

ImportantEmil

Marquee runs unconditionally, including for reduced-motion users mid-page

WhatThe skills marquee animates slide 30s linear infinite. The reduced-motion block kills the CSS animation (good), but for everyone else it is a permanently moving element that never pauses — including while a visitor is trying to read the form directly below it.

Why it mattersAmbient motion that cannot be paused is the accessibility reference's first vestibular concern, and Emil's rule is that motion without a purposeful job gets cut. A skills strip has already been read two seconds after it scrolls into view; after that it is noise competing with the content beneath it.

Recommended motionPause the track on hover (animation-play-state: paused) and add an IntersectionObserver that pauses it whenever the marquee is out of the viewport. Zero cost, removes the permanent-motion complaint.

Issues to address
ImportantJakubEmil

Identical reveal on every section flattens hierarchy

WhatEvery .rv element — section heads, all four project cards, all three process rows, both certificates, the banner — gets the identical 800ms/22px fade-up. That is 12+ elements sharing one entrance treatment, which sits one element short of the anti-checklist's uniformity-slop threshold.

Why it mattersJakub's rule: context drives timing. A section headline and a list row should not arrive with the same weight. Uniform entrances also read as template polish rather than authored rhythm — the exact "same animation everywhere" tell his mistakes list opens with.

Recommended motionTwo-tier reveal: section heads keep 800ms/22px; cards and rows drop to 500ms/12px with a 60-80ms sibling delay inside each grid (one staggered moment per section, not per element). Headline arrives, contents follow quicker.
